# 白屏的两个原因，以及为什么状态码检查永远看不见它们

控制台曾经**完全白屏**，修好后**只有 QQ 接入那一页白屏**。两次都是同一个类别的问题：**服务端一切正常，浏览器里什么都没渲染出来。**

状态码、Content-Type、资源大小、模块语法 —— 全部正确。这就是为什么这类 bug 特别难查，也是为什么需要新的检查手段。

## 原因一：runtime-only Vue 不认识 `template` 字符串

Vite 把 `vue` 解析到 **runtime-only** 构建：

```
vue/dist/vue.runtime.esm-bundler.js
```

它**不含模板编译器**。而根组件当时是这样写的：

```ts
createApp({
  template: `<header class="app-header">…</header>`,   // ← 运行时需要编译器
  setup() { … },
}).mount('#app');
```

**结果：组件挂载成功，渲染出空内容，控制台一行报错都没有。**

`compileToFunction`、`Component provided template option` 这些符号在产物里**全都不存在**，而**原始模板以字符串字面量的形式留在了 bundle 里，从未被使用**。

### 为什么其他页面没坏

6 个视图都是 `.vue` 单文件组件，**构建期就编译好了**。只有根组件用字符串模板 —— 所以整个应用白屏，而不是某一页白屏。

### 修法

根组件也写成 SFC（`App.vue`）。**并加了一条守卫**：`scripts/check-vue-templates.mjs` 同时检查源码里没有 `template:` 选项，以及产物里没有运行时编译器的警告字符串。

## 原因二：模板引用全局变量会抛错

修好根组件后，**QQ 接入那一页仍然白屏**。元凶是模板里的一行：

```html
<td><code>{{ location.origin }}/qq/webhook</code></td>
```

**Vue 模板只在组件实例上查找名字，从不查全局。** 所以 `location` 不是"浏览器的 location"，而是**一个不存在的属性**，读取它**抛出异常** —— 而渲染中抛异常会**清空整个视图**。

浏览器里的证据正是这样：

```
App.vue:48 TypeError: Cannot read properties of undefined (reading 'origin')
    at Proxy.<anonymous> (QqView.vue:126:35)
```

**其他页面不引用 `location`，所以只有这一页坏** —— 这解释了为什么它看起来像"某一页坏了"而不是"应用坏了"。

### 修法

在 `setup` 里取好再暴露给模板：

```ts
const webhookUrl = `${location.origin}/qq/webhook`;   // setup 里用全局是合法的
```

## 为什么状态码检查抓不到

我当时的 `verify-console.mjs` 断言外壳 HTML 里有 `<div id="app">` —— **通过了，而页面全白**。因为失败在 JavaScript 里，而检查只看到了 HTML。

> **一个在 HTML 上停下的检查，看不见发生在 JS 里的失败。**

## 因此新增的两层检查

### 1. 真正执行每个视图的渲染函数（`check-views-render.mjs`）

Vue 自带 SSR 渲染器。用 `vite build --mode ssr` 打一个 Node 可加载的包，**把 7 个组件各渲染一次**。任何未定义引用都会**抛出真实异常**，而不是靠正则匹配名字。

**这比正则扫描强在哪里**：正则只能找到"我想到了要列进去"的名字 —— 拼写错误、改名后的变量、其他全局，全都漏。真正跑一遍能抓住所有。

**为了不误报**，检查器会注入 `location`、`window`、`document` 等浏览器全局 —— 因为 **setup 里用这些是合法的**，只有**模板里**的未定义引用才是 bug。而 Vue 模板不查全局，所以注入它们**不会**掩盖真问题。

### 2. 拒绝检查过期的产物

开发中我遇到过一次：源码改坏了导致构建失败，SSR 包没更新，而检查器**拿着旧包报告"全部通过"**。

> 一个在过期产物上通过的检查工具，比没有工具更糟 —— 它为你从未编译过的代码签了字。

所以检查器会比较 `web/src` 与产物的修改时间，**过期就拒绝运行**。

## 顺带修的两件事

**1. 一个视图抛错不该毁掉整个界面。** 加了 `onErrorCaptured`：错误显示在页面上（含调用栈）而不是白屏，导航仍然可用，可以切到别的页面，并提供「重试」。

原来那个失败**在界面上完全不可见** —— 调用栈才是真正的诊断信息，而它只出现在浏览器控制台里。

**2. 测试产物不能进公开资源目录。** SSR 检查包原本输出到 `web/dist/ssr/`，而 `assets.directory = "web/dist"` —— 它会被**上传并公开提供，无需认证**。已移到 `web/build-test/`，并实测 `/ssr/render-check.js` 返回 404。

## 已考虑并否决

- **改用带编译器的完整版 Vue**（`vue/dist/vue.esm-bundler.js`）：那会把编译器打进产物（约 +30 KB），只为在运行时编译一个本来就能在构建期编译的模板 —— 而且它会让"用字符串模板"变成一个不报错的选择，从而保留整类 bug。
- **只做正则扫描模板**：抓不到拼写错误和改名，而这次两个 bug 中有一个（`location`）恰好能被抓到、另一个（runtime-only）完全抓不到。
- **装 jsdom/puppeteer 做真实浏览器测试**：为一个已知形状的问题引入重量级依赖。SSR 渲染函数能暴露同样的异常，成本几乎为零。
- **让白屏继续白屏，只加日志**：日志要人去翻浏览器控制台 —— 而"页面不显示"的人不会去翻。
