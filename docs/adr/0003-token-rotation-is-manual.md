# 会话令牌只能人工轮换（约 6 小时一次），不设计自动续期

上游的 `POST /api/v0/chat/create_pow_challenge` **不是匿名接口**：不带 Bearer 的请求返回 `200 {"code":40002,"msg":"Missing Token"}`。而所有已知的逆向项目都**没有任何免密码的续期端点**——令牌（`userToken`，浏览器 localStorage 里那一个）约 6 小时失效，之后只能由人在浏览器里重新登录并取出新的。

## 为什么这条值得记下来

因为它**否定了"部署完就不用管"这个隐含期待**。一个看起来像守护进程的系统，实际上每 6 小时需要人手介入一次。这可能与使用者对"部署在 Cloudflare 上的工具"的心理模型冲突，所以必须显式记录，而不是让它在第一次失效时表现为一个莫名其妙的全站 502。

## 后果

- 服务必须把"令牌失效"做成**一等状态**：后台要显眼地显示剩余有效期，失效时接口返回可读的错误而不是把上游的 40002 透传出去。
- 续期流程要有出口：一个受保护的后台入口，粘贴新令牌即生效，不需要重新部署。
- 部署时不存在"设置一次就完事"的密钥。`wrangler secret put` 只是起点。

## 已考虑并否决

- **自动登录**：需要复现浏览器 TLS 指纹（逆向项目普遍用 `curl_cffi` 做这件事），Worker 的 `fetch` 改不了 TLS 指纹，做不到。
- **用无头浏览器维持会话**：Cloudflare Browser Rendering 免费版可用但每天只有 10 分钟，且官方明确说明其流量**始终被识别为机器人**（会带 `cf-biso-request-id`），面对同样架在 Cloudflare 上的 DeepSeek 没有任何优势。
