# 思考与搜索模式：一个能生效但一直没接上的开关，以及一个"看起来生效"的 bug

## 缺口：上游支持，但整个 API 层碰不到

`src/deepseek/client.ts` **从一开始就接受** `thinkingEnabled` 和 `searchEnabled`，并把它们写进 completion 请求体：

```ts
thinking_enabled: req.thinkingEnabled ?? false,
search_enabled: req.searchEnabled ?? false,
```

但**所有调用路径都硬编码成 `false`** —— 没有任何地方能把它打开。

这不是"缺一个功能"，而是**一个已实现的能力被切断在最后一米**。它也不会报错，所以能一直藏着。

## 一个开关要能被三种调用方用到

DeepSeek 网页版是**按会话**开这两个模式的，而调用方有三类，能用的通道各不相同：

| 调用方 | 怎么表达 |
|---|---|
| `/v1` API 调用方 | 直接传字段 `{ thinking: true }` |
| 标准 OpenAI 客户端 | **不能传自定义字段** —— 所以用**模型名**（`deepseek-web-thinking`），这也是生态里已有的做法 |
| QQ 聊天用户 | **完全没有请求字段** —— 所以用**消息开头的指令**（`/think 问题`） |

三条路径都必须落到同一个字段上。

### 指令必须是"开头"而不是"包含"

`解释一下 /think 这个词` 是在**谈论**这个指令，`/think 解释一下` 才是在**使用**它。如果把包含也算上：

- 普通消息会被静默重新解释；
- 而且**再也没法谈论这个功能本身**。

所以只认开头，匹配后还要**把指令从 prompt 里去掉** —— 否则模型会被要求回答 "/think" 这个词。

## 我写出的 bug：算出来了，但没写回去

第一版实现是这样的：

```ts
const thinking = request.thinking ?? (fromModel.thinking || directive.thinking);
const search   = request.search   ?? (fromModel.search   || directive.search);
// ← 到此为止。两个局部变量再没被用过。
```

而下游 `completeOnce` 读的是 **`request.thinking`**。

于是：**显式传字段的那条路径能用**（值本来就在 request 上），**另外两条静默无效**。

**实测证据**（同一个问题，同一时刻）：

```
显式 { thinking: true }            → ctok=27  返回推理过程   ✅
model 名 "deepseek-web-thinking"   → ctok=1   "9"          ❌ 静默无效
"/think 问题"                      → ctok=1   "9"          ❌ 静默无效
```

**三条路径里两条是安慰剂，而且不报任何错。** 一个"看起来生效"的开关比没有开关更糟：使用者会以为自己在用深度思考，实际拿到的是普通回答，然后把结果不好归因于模型。

修法是一行赋值。但**值得记下来的是为什么它没被测出来** —— 单元测试断言了解析器（`parseModes` 是对的），而 bug 在**解析结果到请求的那一步**。所以补了 `test/modes-resolution.test.ts`，它断言的正是"解析出来的值必须落在 request 上"。

> 这也说明为什么**必须打真实的上游**：这个 bug 在纯单元测试里完全隐形，因为每个部件单独看都是对的。

## 模式是看不见的，所以要显式确认

一个开启深度思考的回答，和一个好回答，**长得一模一样**。所以回复末尾会附一行简短的标记（`_（深度思考 · 联网搜索）_`）—— 否则用户按了开关也无从判断它是否生效。

只发指令不带问题时，不发送空 prompt 给上游（那会得到一个针对"什么都没有"的通用回复），而是**确认模式已切换**。

## 实测

```
plain                    → ctok=1,  1500ms, "9"
thinking（显式）         → ctok=27, 2041ms, 推理过程  ✅
thinking（模型名）       → ctok=25, 1505ms, 推理过程  ✅
thinking（/think 指令）  → ctok=25, 1977ms, 推理过程  ✅
search（联网）           → ctok=24, 2621ms, 带 [citation:2] 的实时新闻  ✅
```

搜索模式返回的是**带引用的实时内容**（巴拿马地震、俄罗斯柴油），说明它真的在联网，而不只是换个提示词。

## 已考虑并否决

- **只加显式字段**：标准 OpenAI 客户端传不了自定义字段，QQ 用户更没有请求体可用 —— 等于功能对多数调用方不可达。
- **指令用包含匹配**：会静默重解释普通消息，且无法再谈论该功能。
- **把指令原样留给模型**：模型会被要求回答 "/think" 这个词。
- **不加模式标记**：用户无法区分"深度思考生效了"和"这次回答碰巧不错"。
