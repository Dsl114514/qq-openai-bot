# 出站消息：Markdown、引用、昵称、指令、对话历史

这一批功能里，**每一条都建立在一个被验证过的事实上**，而不是文档里的假设。下面记的是那些事实和由它们推出的决定。

## Markdown 不需要申请（2026/04/23 起）

官方文档明确：**单聊和群聊场景的自定义 Markdown 已对所有机器人开放，无需单独申请**（频道场景仍需内邀）。所以 `msg_type: 2` 可以直接用。

一个容易踩的细节：**Markdown 消息必须带 `markdown` 字段，且 `content` 必须为空** —— 同时传两个是错误，不是偏好。这在 `buildSendBody` 里被结构性地保证（两种模式互斥），而不是靠调用方记得。

**实测**：往真实群里发了一段带标题、列表、加粗、行内代码的 Markdown，QQ 返回成功。

### 但内容不能直接信

QQ 比浏览器渲染器严格得多：**一个格式错误会让整条消息发送失败**，而不是降级显示。所以 `toMarkdownSafe` 主动去掉最可能失败的三类东西：

| 去掉 | 为什么 |
|---|---|
| 图片 `![alt](url)` | QQ 会下载并转存图片，模型编的 URL 几乎必然失败，而**转存失败会导致整条消息失败**。保留 alt 文本，信息不丢 |
| 表格 | 不在支持的子集里，渲染成噪音 |
| 水平线、HTML 标签 | 同样不支持 |

**代码块保留** —— 它是支持的，而且对这个机器人最有用。

### 自动检测 + 失败回退

不是所有回复都值得用 Markdown 发：一句普通的话用 Markdown 发出去长得一样，却多一个失败模式。所以 `looksLikeMarkdown` 只在文本**真的含有**受支持的构造时才启用，而且如果 QQ 拒绝了这个自动判断，**自动改用纯文本重发** —— 一个能读的纯文本回复胜过一条发送失败的消息，因为后者与"机器人挂了"无法区分。

## 引用回复的索引来自事件

QQ 支持 `message_reference` 引用回复，需要 `msg_idx`。实测真实事件里确实带着它：

```json
"message_scene": { "ext": ["msg_idx=REFIDX_G/Qznqi1YZFjZ0Vb...", "auth_token=..."] }
```

所以引用不需要额外请求，事件里就有。索引**原样使用**：它是不透明的，含 `=`、`+`、`/`，任何"规整化"都会破坏它。

要注意**引用和被动回复是两件事**：

- `msg_id` 让回复在被动窗口内合法（决定**能不能发**）；
- `message_reference` 让回复**视觉上引用**那条消息（决定**好不好读**）。

早期代码只有前者，所以对话读起来是一串没有锚点的回答。

## 昵称：让 transcript 有人名

QQ 在群事件里带 `author.username`（实测：`"Chrono/VERT"`），这是唯一可读的名字。不存它的话，喂给模型的 transcript 就是一串 openid，"接一句群友的话"会变成对着谁都不是的话发言。

**按群作用域存储**：同一个人在不同群里可以叫不同名字，把 A 群的昵称用在 B 群的 transcript 里，读起来像陌生人说话。

**未知发送者的回退保留 id 两端**（`ABCD…WXYZ`）而不是只取前缀。群里的人 openid 常有很长的共同前缀，只取前缀会让几个人塌缩成同一个标签 —— 那正是回退要避免的混乱。

## 指令面板：发现路径才是关键

`/reset` 早就存在，但**没有任何地方告诉用户它存在**。一个没人知道的指令和一个不存在的指令，从用户角度看完全一样。

所以 `/help` 不是装饰，它是其他指令可用的前提。新增：

| 指令 | 作用 |
|---|---|
| `/help` | 列出指令 + 说明当前会话状态 |
| `/reset` | 开新会话 |
| `/status` | 会话状态（日期、是否延续） |
| `/ping` | 存活确认 |

**指令的匹配是精确的，不是前缀**：以斜杠开头的消息更可能是路径或日期（`/usr/local/bin`、`/2026-10-10`），吞掉它们会看起来像机器人在无视用户。有测试钉住这一点。

指令回复**用 Markdown 发** —— `/help` 是个列表，而列表正是 Markdown 存在的意义。

## 对话历史：另一种视角，不是替代

审计台是**按调用**看：一行一次请求，正文是原始 JSON。这回答"到底发了什么"，是调试需要的。

但它不回答"这个群最近在聊什么" —— 那需要按顺序读很多行，并逐条解析正文找文本。`/admin/history` 做这个提取，让对话**可读**而不是需要重建。原始正文仍然一键可达，所以这是透镜，不是替代。

## 顺带修的两个静默失败

1. **手动发送没有落库。** 「立刻发一条」走的是独立路径，没有写 `call_log`。于是"测试发送成功了吗"只能去群里看 —— 而这恰恰是审计台存在的意义。现在它与定时发送记录在同一处。

2. **群标识可以填错而毫无提示。** 见 [ADR-0015](0015-group-id-must-be-selected-not-pasted.md)。

## 已考虑并否决

- **所有回复都用 Markdown**：多一个失败模式，换不到任何视觉差别。
- **保留图片 Markdown 让 QQ 自己处理**：转存失败会让整条消息失败，而模型编的 URL 几乎必然失败。
- **不存昵称，transcript 里用 openid**：模型会对着 id 说话，效果等于没有上下文。
- **指令用前缀匹配**：会把路径和日期当成指令吞掉。
- **让对话历史取代审计台**：提取后的文本会丢掉字段、状态码和原始结构，而那正是调试要看的。
